# 可维护性审计与重构路线

## 1. 当前结论

项目的主要功能和自动化门禁可以运行，但当前工作区改动规模过大，且若干文件承担了过多职责。现阶段不适合继续“一把梭”重写，应该先形成可提交基线，再按业务域拆分。

## 2. 已量化的热点

以下行数来自 2026-09-17 的工作区快照，仅用于排序，不代表代码质量本身：

| 文件 | 约行数 | 主要风险 |
| --- | ---: | --- |
| `backend/imports/import_orchestrator.py` | 1625 | 提取、切块、调用、容错和合并集中，改动影响面大 |
| `frontend/src/views/ImportQuestions.vue` | 1478 | 上传、任务轮询、预览、课程选择和样式耦合 |
| `frontend/src/views/CourseList.vue` | 1387 | 查询、筛选、管理菜单、编辑与视觉样式集中 |
| `backend/schemas.py` | 882 | 多业务域 schema 集中，合并冲突高 |
| `frontend/src/components/import/ImportPreview.vue` | 839 | 预览编辑状态与渲染逻辑偏重 |
| `frontend/src/views/Practice.vue` | 724 | 多题型、会话、结果、手势和响应式样式耦合 |
| `frontend/src/layouts/AppLayout.vue` | 557 | 导航、搜索、键盘、主题和布局集中 |

## 3. P0：先形成干净基线

1. 暂停跨模块大改，确认每个未提交文件的所有者。
2. 删除或忽略日志、数据库、上传、构建和临时截图。
3. 按“迁移/后端域/前端域/文档”拆分提交，每个提交独立通过相关测试。
4. 在干净检出上执行 CI 全门禁，再创建版本标签。
5. 生产环境设置唯一 `SECRET_KEY`、`INVITE_CODE`、明确 CORS 和正式数据库。

完成标准：`git status` 干净；CI 全绿；迁移可从空库升级；安全检查通过。

## 4. P1：拆分 AI 导入域

建议边界：

- `extractors/`：Word、PDF、PPT、图片文字与媒体提取。
- `chunking/`：文本分段和题目边界策略。
- `providers/`：OpenAI 兼容调用、超时与重试。
- `parsing/`：JSON 修复、题目校验、去重与告警。
- `tasks/`：任务状态、进度、恢复和临时文件生命周期。

前端把上传选择、任务状态、预览编辑、课程目标和确认导入拆成独立组件/composable。拆分前先补契约测试，保证同一文档的有效题目、告警和状态迁移不变。

## 5. P2：统一后端域边界

- 按 `auth`、`courses`、`practice`、`imports`、`exams`、`analytics` 拆分 schema。
- 逐域统一 `routers/` 与 `api/`，不要一次移动全部文件。
- 控制层只做参数/权限/响应；事务和业务规则进入 service；查询细节进入 repository。
- 每迁移一个域，保持原 URL、状态码和 response model，并运行对应测试。

## 6. P3：前端页面瘦身

- `CourseList.vue`：拆出筛选栏、题库列表项、管理菜单和编辑弹窗。
- `Practice.vue`：保留流程协调，把题型呈现、结果、总结和导航下沉到组件。
- `AppLayout.vue`：把底部导航、全局搜索和 viewport/keyboard 处理拆为独立单元。
- 页面只负责组合，API 请求放在 `api/`，业务状态放在 composable/store。

建议目标：页面文件尽量控制在 500 行以内；单个函数只承担一种业务意图。行数是提醒指标，不作为机械验收条件。

## 7. P4：可观测性与实验材料

- 为导入任务记录 request ID、块数、有效题数、重试次数和阶段耗时。
- 为关键接口记录结构化错误类型，而不是只记录字符串。
- 建立匿名化导入评测集，固定预期题目数量和关键题干。
- 在论文实验中对不同文档类型、长度和模型配置进行对比。

## 8. 每轮重构验收模板

1. 本轮只处理一个业务域。
2. 记录改前的接口契约和测试结果。
3. 拆分结构但不同时改产品行为。
4. 运行域测试、全量测试、构建和安全检查。
5. 更新操作留档，单独提交并推送。
