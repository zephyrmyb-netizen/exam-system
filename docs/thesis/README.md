# 学习宝课程设计与毕业论文材料

本目录把“能运行的项目”整理成“可以说明、可以验证、可以答辩的项目”。材料以当前代码为依据，不把规划中的功能写成已经完成。

## 阅读顺序

1. [系统架构与核心流程](./01-system-architecture.md)：说明系统由哪些层组成，以及 AI 导入、刷题和考试如何流转。
2. [数据库设计](./02-database-design.md)：说明核心实体、关系、唯一约束和删除策略。
3. [测试方法与当前证据](./03-testing-and-evaluation.md)：给出可重复执行的测试命令和最近一次结果。
4. [论文写作提纲](./04-thesis-outline.md)：把代码证据映射到论文章节。
5. [可维护性审计与重构路线](./05-maintainability-roadmap.md)：记录当前技术债及其分阶段治理方案。

## 项目定位

学习宝是面向个人学习与小组复习的题库系统。系统覆盖题库与题目管理、Word/PDF/PPT/图片导入、AI 结构化解析、随机练习、错题与间隔复习、正式考试、学习统计、收藏、公开题库和学习小组。

论文中建议把研究重点收敛为三个问题：

- 如何把非结构化学习资料稳定地转换为可编辑、可确认的结构化题目。
- 如何用练习记录、错题聚合和间隔复习状态形成学习闭环。
- 如何通过权限、幂等提交、迁移、自动化测试和安全检查保证系统可靠性。

## 答辩材料建议

- 演示路径：登录 -> 创建题库 -> 导入并确认题目 -> 开始练习 -> 查看错题/统计 -> 创建考试。
- 架构图：直接使用 `01-system-architecture.md` 中的 Mermaid 图导出图片。
- ER 图：使用 `02-database-design.md` 中的核心 ER 图。
- 测试数据：答辩前重新执行 `03-testing-and-evaluation.md` 中的命令，并记录日期与结果。
- 安全说明：演示环境可以使用 SQLite；公开部署必须更换 `SECRET_KEY`、`INVITE_CODE`，并设置明确的 `CORS_ORIGINS`。

## 真实性边界

- 当前后端同时存在 `backend/routers/` 与 `backend/api/` 两组路由目录，这是逐步分层过程中的现实结构，不应在论文中描述为已经完全统一。
- AI 解析效果依赖上游模型、文档质量和切块策略。论文应展示可复现样本、失败样本与人工确认机制，不应只写“识别准确率高”。
- SQLite 适合本地演示；多人部署应使用 PostgreSQL，并考虑 Redis 限流和多 worker 场景。
