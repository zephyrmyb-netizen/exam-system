# 学习宝参考 UI 逐页一致性规格

**日期：** 2026-07-14
**状态：** 已获用户确认，待实现前审核
**范围：** Vue 前端参考 UI 的 8 页高保真结构与视觉对齐；不修改后端契约、数据库或业务状态机。

## 1. 目标与判定

目标不是“风格相近”，而是在 390 × 844 的手机视口下，使每个 Vue 页面与对应 `exam-platform-ui/pages/*.html` 参考页具有相同的：

- 模块顺序与页面层级；
- 顶部、主卡片、主要操作区与底部导航的占位、尺寸和间距；
- 信息密度、卡片数量、留白、圆角、字体层级与绿色视觉语言；
- 数据状态（真实、空、加载、失败）下的稳定布局。

真实接口内容可以不同；内容不同不得改变参考页的模块骨架。接口未提供的字段显示 `--` 或真实空状态，不使用参考稿的示例数字填充。

## 2. 非目标与约束

- 不改动 API 路径、请求/响应结构、数据库、权限或 Pinia/XState 业务契约。
- 不把 `frontend-preview.html` 当作设计输入，也不纳入交接包；它是旧“墨韵”预览。
- 不新建练习完成路由；完成态仍由会话内 `PracticeSummaryModal.vue` 呈现。
- 随机练习没有完整题序时，不伪造参考稿中的固定答题卡或题目总数。
- 考试答题卡只能使用后端返回的真实试卷题序。
- 既有标签页使用 `router.replace`，来源感知返回逻辑保持不变。

## 3. 视口与应用壳

| 范围 | 行为 |
| --- | --- |
| 320–759px | 流式手机布局，无横向溢出。 |
| 390–420px | 参考稿对照基准。 |
| ≥760px | 页面外显示背景与阴影，应用内容壳固定为 420px 宽。 |

普通页统一为“顶部内容区 → 可滚动主内容 → 固定四项底栏”；底栏为首页、题库、导入、我的。导入页拥有自己的标题，不能出现重复页头。

题库练习和考试答题为沉浸模式，不出现四项底栏。练习完成态以遮罩弹窗存在，但弹窗内部的结果、统计和操作布局应对齐参考完成页。

所有页面共享字体、色板、圆角、玻璃层、阴影、渐变、间距和安全区变量；页面不得再各自定义接近但不一致的视觉值。

## 4. 逐页结构规格

| 参考页 | Vue 路由与实现 | 必须一致的视觉骨架 | 保留行为 |
| --- | --- | --- | --- |
| 首页 | `/` · `Home.vue` | 绿色欢迎区 → 今日学习总览卡 → 快捷入口/推荐 → 最近题库列表 | 真实用户名、连续天数、学习统计、推荐和现有入口。 |
| 题库列表 | `/courses` · `CourseList.vue` | 顶部标题与搜索 → 四类筛选标签 → 紧凑题库卡片列表 → 创建入口 | 搜索、筛选、创建、编辑、发布、删除、练习方式底部面板。 |
| AI 导入 | `/import` · `ImportQuestions.vue` | 独立标题 → 大型上传面板 → 导入方式与格式提示 → 任务进度/预览确认 | 文件校验、异步恢复、分块进度、JSON/手动导入。 |
| 我的 | `/mine`（兼容 `/profile`） | 绿色账号头图 → 三项统计 → 功能入口网格 → 主题/退出区 | 真实账号、统计、连续学习、错题、收藏、记录、AI、主题、退出。 |
| 题库练习 | `/courses/:courseId/practice`（兼容 `/practice/:courseId`） | 沉浸顶部进度/退出 → 题干与题型 → 选项区 → 解析与操作区 | XState 会话、题型输入、提交、自动下一题、离线同步。 |
| 练习完成 | `PracticeSummaryModal.vue` | 遮罩 → 成就/结果区 → 统计卡 → 继续或返回操作 | 保持会话内弹窗，无伪造完成路由。 |
| 考试答题 | `/exams/:examId/take`（兼容 `/exam/:examId`） | 考试标题/倒计时 → 题号与题干 → 选项 → 答题卡与导航 → 交卷确认 | 真实倒计时、题序、键盘/滑动、退出确认、超时交卷、重复提交保护。 |
| 考试完成 | `/exams/:examId/result` · `ExamResult.vue` | 成绩主视觉 → 用时/正确率统计 → 逐题结果 → 排行榜入口 | 真实得分、用时、逐题结果与排行榜入口。 |

## 5. 数据和状态规则

- 首页和我的直接使用 `useStudyOverview` 提供的 `streak`、`recommendation` 和真实统计；禁止继续显示本可获得的 `--`。
- 后端未提供的等级、徽章等数据不从题目数量推导，也不复制静态示例值。
- 空、加载或接口部分失败时，保留当前页面对应区块的高度与顺序，改为显示真实状态提示。
- 固定视觉测试可使用受控模拟数据；正式运行只显示真实数据。

## 6. 实施顺序与验收门槛

实施严格串行，前一页未达到结构一致性不得进入下一页：

1. 公共壳层、字体、令牌、底栏和安全区；
2. 首页；
3. 题库列表；
4. 我的；
5. AI 导入；
6. 题库练习与完成弹窗；
7. 考试答题；
8. 考试完成。

每页按以下两轮验收：

1. **结构轮**：在 390 × 844 浅色模式下与对应参考 HTML 并排审核。模块顺序、主要区块尺寸、位置、信息密度、留白、圆角层级和固定操作区必须一致。
2. **视觉轮**：在结构通过后，继续收敛字体字重、行高、色值、渐变、阴影、图标与微间距。

每页还必须在 320 × 720、420 × 900 下无横向溢出、底栏遮挡或安全区错误；四个主标签页须有深色模式冒烟截图。

最终验收：

```text
npm.cmd run lint
npm.cmd run test -- --run
npm.cmd run test:visual
npm.cmd run build
git diff --check
python scripts/security_check.py
```

全部页面通过后才更新视觉基线，并用同一通过验收的 commit 重新生成 Codex 交接 ZIP。

## 7. 审核结论

用户已逐段确认：

1. 8 页全部逐页对齐；
2. 390 × 844 下参考 HTML 的布局与视觉密度为硬基准；
3. 采用“结构先行、逐页验收”，而非直接像素级 CSS 覆盖或大段静态 HTML 移植；
4. 公共壳、主标签页、沉浸流程及验收门槛均按本文件执行。

下一步必须先取得本规格文档的审核确认，之后再编写实现计划并修改代码。
